# Индексы в PostgreSQL

## Зачем нужны индексы

Индексы позволяют PostgreSQL находить строки без
необходимости сканировать всю таблицу.

## Когда индекс может не использоваться

Планировщик запросов может выбрать последовательное
сканирование, если считает его дешевле индексного.
Это возможно, например, когда запрос возвращает
значительную часть таблицы.

## Создание индекса

Для создания индекса можно использовать команду:

CREATE INDEX idx_users_email ON users (email);

## Виды индексов

### B-tree

индекс по умолчанию в Postgresql. Стандартный для запросов по
равенству и диапазонов. (=, <, >, BETWEEN, ORDER BY)
`CREATE INDEX idx_users_email ON users(email);`

### GIN

для массивов и JSON. Подходит когда в одном поле много значений и
мы ищем по вхождению.
`CREATE INDEX idx_users_tags ON users USING GIN(tags);`

### HASH

на практике почти не используется. Только для =

## Сканы

### Seq Scan

PostgreSQL читает таблицу полностью

Используется когда:
- маленькая таблица
- нет подходящего индекса
- planner считает, что дешевле прочитать все

### Index Scan

PostgreSQL идет по индексу и только потом в таблицу за строкой

Используется когда:
- селективность высокая, то есть проиндексированный столбец содержит большое
  кол-во уникальных значений
- подходит мало строк

### Bitmap Index Scan

PostgreSQL собирает список подходящих строк(bitmap), а потом читает их пачкой.
Компромисс между Seq Scan и Index Scan

Используется когда:
- подходит много строк
- но и не вся таблица
